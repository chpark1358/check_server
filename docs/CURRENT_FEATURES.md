# Current Features

이 문서는 현재 배포 기준으로 적용된 주요 기능과 운영 정책을 정리한다.

운영 규칙:
- 기능, 보안, UI, API 동작이 바뀌는 작업 뒤에는 이 문서를 갱신한다.
- 상세 작업 이력은 `docs/WORK_LOG.md`에 기록한다.
- 이 문서는 최신 상태 요약을 유지하고, 과거 변경 이력은 길게 누적하지 않는다.

마지막 갱신:
- 날짜: 2026-05-18
- 기준 브랜치: `codex/preview-sandbox`
- 운영 URL: https://check-server-site.vercel.app
- Preview URL: https://check-server-site-loo4p1co0-chpark425-3494s-projects.vercel.app

## 화면 구성

- `점검 데이터`: CRM 로그인, 시리얼 기준 점검 데이터 조회, 점검 결과 확인, DOCX/PDF 생성.
- `일괄 점검`: 여러 시리얼 점검, 고객사 담당자 매핑, 일괄 PDF 생성, Zendesk 테스트/실제 전송.
- `젠데스크 메일 발송`: Zendesk 조직 매칭, 메일 미리보기, 테스트 전송/실제 전송, PDF 첨부 발송.
- `이력`: 점검 조회, 점검서 생성, 메일 발송 이력을 한 화면에서 조회.
- `문서함`: 생성된 DOCX/PDF 문서 조회, 다운로드, PDF 메일 첨부.
- `설정`: 사용자별 기본 점검자, 서버 모델, Iptables 상태, 발송 모드, 자동 해결 처리 기본값 저장.
- `관리자`: 관리자 권한 사용자만 접근 가능한 사용자/초대/감사 로그 화면.

## 접근 제어

- Vercel production 배포를 사용한다.
- Vercel alias는 `https://check-server-site.vercel.app`이다.
- 공인 IP 접근 제한은 Vercel Firewall 쪽에서 관리한다.
- 앱 내부 API는 역할 기반 권한을 사용한다.
- 역할은 `조회자`, `운영자`, `관리자`로 구분한다.
- 관리자 메뉴는 관리자 권한 사용자에게만 노출한다.

## 앱 로그인

- 로그인 화면 제목은 `점검 시스템 로그인`으로 표시한다.
- 로그인 화면에서는 `운영자 계정`, `Supabase` 같은 구현체 또는 역할 중심 문구를 노출하지 않는다.
- 로그인 실패 시 사용자용 메시지를 표시한다.
  - `이메일 또는 비밀번호가 올바르지 않습니다.`
  - `이메일 인증이 완료되지 않았습니다. 초대 메일을 확인하세요.`
  - `로그인 시도가 많습니다. 잠시 후 다시 시도하세요.`

## 점검 데이터

- CRM 계정으로 로그인한 뒤 시리얼 기준으로 점검 데이터를 조회한다.
- CRM 토큰은 httpOnly cookie에만 저장한다.
- 점검 결과 상단 요약에는 점검 API 수집일 배지를 표시한다.
- 브라우저에는 비밀값이 아닌 세션 메타데이터만 저장한다.
  - `username`
  - `masked`
  - `expiresAt`
- 탭 이동 또는 새로고침 시 localStorage 세션 메타데이터로 CRM 로그인 표시를 복구한다.
- 세션 만료 또는 로그아웃 시 저장된 세션 메타데이터를 삭제한다.
- 시리얼 검색값은 저장하지 않는다.
- 다른 시리얼의 점검 데이터를 새로 불러오면 기존 생성 문서와 메일 첨부 상태를 초기화한다.
- 점검 결과 디스크 라벨은 다음처럼 표시한다.
  - `/ 파티션`
  - `/home 파티션`
  - `/storage 파티션`
- 서비스 상태명은 한글 업무명으로 표시한다.
- 라이선스 요약은 `사용 N / 총 N`, `미인증 N · 사용률 N%` 형식으로 표시한다.
- Load Average는 CPU 카드에서 분리하고 별도 카드에 1분, 5분, 15분 값을 표시한다.
  - `에이전트 연결`
  - `메일 서버`
  - `웹 접속`
  - `웹 서비스`
  - `DB 서비스`
  - `시간 동기화`
  - `방화벽 정책`
  - `Firewalld`
  - `백업`
- `메일 서버`는 점검서 제외 항목으로 표시한다.
- Firewalld는 `FileNotFound`, `StatusNotActive` 계열 상태를 서비스 미설치 또는 비활성 허용으로 보고 정상 처리한다.
- 원본 주요 값도 한글 라벨로 표시한다.

## Preview 일괄 점검

- `codex/preview-sandbox` Preview 환경에서만 우선 검증하는 기능이다.
- 시리얼은 `LO` 프리픽스를 고정 표시하고 숫자만 입력하는 다중 입력칸으로 순차 조회한다.
- 시리얼 입력칸에서 Enter를 누르면 일괄 조회를 실행한다.
- 중복 시리얼은 정규화 후 한 번만 조회한다.
- 정상/검토 필요 판정과 고객사 담당자 매핑 여부를 처리 목록에 표시한다.
- 검토 필요 항목은 서비스 실패, 경고, 미인증 라이선스, CPU/메모리, 파티션 사용률 기준 사유를 함께 표시한다.
- 매핑 완료 항목은 요청자 이메일과 Zendesk 조직 ID를 함께 표시한다.
- 처리 목록의 `상세` 버튼으로 기존 점검 데이터 탭과 같은 점검 결과 요약을 일괄 화면에서 미리볼 수 있다.
- 조회 완료된 항목은 매핑 여부와 무관하게 수동 선택할 수 있다.
- 저장된 매핑으로 자동 연결되지 않은 항목은 처리 목록에서 매핑을 수동 선택해 연결할 수 있다.
- 일괄 Zendesk 발송이 성공한 수동 매핑은 시리얼 기준으로 저장되어 다음 동일 시리얼 조회 시 자동 매칭된다.
- 선택 보조 버튼은 `정상 항목 선택`, `매핑 완료 선택`으로 분리한다.
- 정상 판정 기준은 주요 서비스 실패 없음, 경고 없음, 미인증 라이선스 없음, CPU/메모리 75% 미만, 최대 디스크 사용률 80% 미만이다.
- 일괄 조회 후 확인 필요 사유가 없는 항목은 자동 선택한다.
- 에이전트 연결 이상만 있는 항목은 `agent`, `agentStatus`, `checkAgentConnection` 등 서비스 플래그 또는 경고 문구로 수집되어도 판정에는 `검토 필요`로 표시하지만 자동 선택 대상에는 포함한다.
- 파티션 사용률이 80% 이상인 항목도 자동 선택 대상에는 포함한다.
- 미인증 라이선스는 일괄 자동 선택 차단 조건에서 제외한다.
- 메일 서버와 Firewalld 계열 상태는 점검서 제외/허용 정책을 반영해 일괄 정상 판정에서 제외한다.
- 고객사 담당자 매핑은 고객사명 검색, Zendesk 조직 선택, 요청자 자동/수동 선택 후 사용자별 Supabase `customer_mail_mappings` 테이블에 저장한다.
- 서버 저장소가 비어 있거나 아직 마이그레이션이 적용되지 않은 환경에서는 기존 브라우저 localStorage 매핑을 fallback으로 사용한다.
- 서버 저장소가 비어 있고 기존 브라우저 저장값이 있으면 첫 조회 시 서버 저장소로 이관을 시도한다.
- 고객사명 입력칸에서 Enter를 누르면 Zendesk 조직 검색을 실행한다.
  - 고객사명
  - Zendesk 조직 ID
  - 요청자 이름/이메일
- 선택된 점검 항목은 기존 점검서 생성 API로 DOCX/PDF를 생성한다.
- 일괄 처리 목록의 PDF/Zendesk 컬럼은 생성 여부와 첨부 여부를 요약 표시한다.
- 일괄 처리 목록의 PDF 생성 완료 항목에서 PDF 미리보기를 바로 열 수 있다.
- 생성된 파일명, 용량, Zendesk 첨부 파일명은 `상세` 미리보기 영역에 표시한다.
- 일괄 Zendesk 발송은 PDF와 고객사 담당자 매핑이 모두 있는 항목만 대상으로 한다.
- 일괄 Zendesk 발송도 단건 발송처럼 `테스트 전송`과 `실제 전송`을 선택할 수 있다.
- 실제 전송은 production 환경이고 `ALLOW_REAL_ZENDESK_SEND=true`일 때만 활성화되며, 전송 전 선택 건수와 요청자 이메일을 확인한다.
- Zendesk 컬럼에는 PDF 첨부 확인 상태를 표시한다.
- 일괄 Zendesk 발송은 한 번에 최대 10건까지만 실행한다.
- 조회, PDF 생성, Zendesk 발송 중에는 현재 단계와 진행률을 표시한다.
- 실패 항목은 별도 버튼으로 다시 선택해 재시도할 수 있다.
- 일괄 발송은 사용자, 전송 모드, 문서, 시리얼, 요청자 기준의 안정적인 중복 방지 키를 사용한다.
- 테스트 전송 완료 항목은 실제 전송 모드에서 다시 발송 대상으로 잡히며, 실제 전송용 중복 방지 키는 별도로 생성한다.
- 일괄 발송 전 확인창에서 항목별 고객사, 시리얼, 요청자, 점검자, 제목, PDF 파일명, 메일 본문을 확인한다.
- 일괄 실제 전송 티켓은 발송 후 자동 해결 처리하며 Zendesk `점검 자동화` 필드를 체크한다.
- 이 기능은 Preview에서 먼저 검증하며, 고객사 담당자 매핑은 Supabase 영구 저장 구조로 전환 중이다.

## 점검서 생성

- 점검 데이터 기준으로 DOCX/PDF 점검서를 생성한다.
- 생성된 PDF는 메일 발송 탭에서 첨부 대상으로 사용할 수 있다.
- 생성된 PDF는 점검 데이터 탭과 문서함에서 새 탭 미리보기로 확인할 수 있다.
- 생성된 PDF 첨부 토큰이 탭 이동 또는 미리보기 이후 사라지면 메일 발송 탭 진입 시 자동 재첨부한다.
- 점검자 선택값과 사용자별 서명 정보를 문서 생성에 반영한다.
- 서버 모델은 자동 판정값을 기본으로 사용하되, 사용자가 선택하면 선택값을 문서에 반영한다.
- AWS 계열 서버 모델은 점검서 서버 모델에 `AWS`로 반영한다.
- Virtual/Virtual Machine 계열은 `VM`으로 반영한다.
- CPU 점유율은 점검서에서 `%` 없이 표시하고, `0.0`은 `0.1`로 보정한다.
- iptables 상태는 사용자가 점검서 기준으로 선택할 수 있다.
- 월간 리포트 상태가 `Y(YYYY-MM)` 형태로 수집되면 최근 리포트 생성일에 `YYYY-MM`을 표시한다.
- 월간 리포트와 iptables의 원본 오류 문자열은 점검서 결과 문구에 직접 노출하지 않는다.

## Zendesk 메일 발송

- Zendesk 조직은 시리얼 기준 자동 매칭을 우선한다.
- 담당자는 솔루션팀 계정으로 고정한다.
- 티켓 제출자와 티켓 처리자 커스텀 필드는 선택된 점검자명으로 Zendesk 필드 옵션을 매칭해 반영한다.
- Zendesk 필드 옵션은 `name`, `raw_name`, `value`, 부분 일치 기준으로 매칭하며, 옵션 `name`과 `value`가 같거나 `value`가 `점검자명_처리자` 형태인 경우도 정상 매칭으로 처리한다.
- 발송 모드는 사용자가 선택한다.
  - `기본 발송 모드`
  - `테스트 전송`
  - `실제 전송`
- `기본 발송 모드`는 설정 탭에 저장된 사용자 기본값을 적용한다.
- 메일 본문은 설정 탭의 사용자별 템플릿을 사용할 수 있다.
- 메일 본문 템플릿은 `{{requesterName}}` 또는 `{{담당자명}}` 치환자를 지원한다.
- 메일 본문 템플릿은 Supabase `user_preferences.mail_body_template`에 저장한다.
- 서버 컬럼이 아직 적용되지 않은 환경에서는 기존 브라우저 localStorage 템플릿을 fallback으로 사용한다.
- 서버 템플릿이 비어 있고 기존 브라우저 저장값이 있으면 첫 설정 조회 시 서버 저장소로 이관을 시도한다.
- production이 아닌 환경에서는 실제 발송을 차단한다.
- 테스트 전송은 Zendesk 티켓을 실제 생성하지 않는다.
- 발송 전 확인 모달에서 조직, 요청자, 그룹, 담당자, 발송 모드, 제목, 첨부, 해결 상태 처리 여부를 확인한다.
- 메일 본문 하단에는 Supabase Storage의 `public-assets/mail/jiransoft_sign_next.png` 서명 이미지를 붙여 전송한다.
- 생성된 PDF는 메일 첨부 대상으로 자동 연결한다.
- 실제 전송/테스트 전송 전환 시 생성 PDF는 현재 발송 모드 기준으로 자동 재첨부한다.
- 티켓 생성 후 해결 처리에 실패해도 생성된 티켓 ID/URL은 보존하고, 해결 처리 실패는 별도 감사 로그와 오류 요약으로 남긴다.
- 티켓 생성 성공 메시지에는 Zendesk 티켓 번호를 클릭 가능한 링크로 표시한다.
- 발송 후 해결 상태 처리 시 필수 커스텀 필드와 `solved` 상태를 같은 Zendesk 요청으로 적용한다.
- 발송 후 해결 상태 처리를 선택하면 Zendesk `점검 자동화` 체크박스 필드(`58864476958489`)를 활성화한다.
- 요청자를 변경하면 본문을 직접 편집한 상태에서도 기존 담당자명만 새 요청자명으로 교체한다.
- 문서함에서도 PDF 생성 완료 문서를 메일 첨부로 보낼 수 있다.
- 발송 이력에서는 내부 상태값 대신 사용자용 라벨을 표시한다.
  - `성공`
  - `실패`
  - `테스트`
  - `대기`
  - `자동 해결`

## 이력 탭

- `GET /api/history/overview` API로 점검 조회, 문서 생성, 메일 발송 이력을 통합 조회한다.
- 일반 이력 탭은 관리자 포함 모든 역할에서 본인 이력만 조회한다.
- 전체 운영자 로그는 관리자 메뉴에서만 조회한다.
- 기간, 유형, 상태, 검색어 필터를 제공한다.
- 검색어 입력 후 Enter를 누르면 검색 버튼과 동일하게 조회한다.
- 상단 요약 카드로 점검 조회, 문서 생성, 메일 발송, 실패 건수를 DB count 기준으로 표시한다.
- 문서/메일 이력 검색은 Supabase 쿼리 단계에서 핵심 컬럼을 검색한다.
- 점검 조회 감사 로그 검색은 `target_id`, `serial`, `company_name`, `search_text` 기준으로 조회한다.

## 문서함 탭

- `GET /api/documents` API로 생성 문서 목록을 조회한다.
- 일반 문서함 탭은 관리자 포함 모든 역할에서 본인 생성 문서만 조회한다.
- 전체 문서 생성 이력은 관리자 메뉴에서만 조회한다.
- 문서 상태, PDF 첨부 가능 여부, 검색어 필터를 제공한다.
- 검색어 입력 후 Enter를 누르면 검색 버튼과 동일하게 조회한다.
- 문서 검색과 요약 숫자는 Supabase 쿼리 단계에서 계산한다.
- DOCX/PDF 다운로드 링크를 제공한다.
- PDF 생성 완료 문서는 새 탭 미리보기를 제공한다.
- PDF 생성 완료 문서는 메일 첨부로 바로 사용할 수 있다.

## 설정 탭

- 사용자별 개인 설정은 Supabase `user_preferences` 테이블에 저장한다.
- 저장 가능한 항목:
  - 기본 점검자
  - 기본 서버 모델
  - 기본 Iptables 상태
  - 기본 발송 모드
  - 발송 후 해결 상태 처리 기본값
  - 메일 본문 템플릿
- 설정된 기본값은 다음 로그인 또는 다음 세션 접속 시에도 유지한다.
- localStorage 설정은 서버 설정 조회 실패 시 fallback 용도로만 사용한다.

## 관리자 메뉴

- 관리자 메뉴는 관리자 권한 사용자에게만 노출한다.
- 관리자 overview에서 다음 정보를 확인한다.
  - 24시간 이벤트 수
  - 점검서 생성 수
  - 메일 발송 수
  - 발송 실패 수
  - 초대 대기 수
- 감사 로그에서 내부 action key 대신 한글 작업명을 표시한다.
- 감사 로그 대상 컬럼은 내부 target type 대신 한글 대상명으로 표시한다.
- 관리자 검색/필터는 API 요청에 반영한다.
- 관리자 검색어 입력 후 Enter를 누르면 검색 버튼과 동일하게 조회한다.
- 관리자 로그 검색 form 제출은 감사 로그에 남긴다.
- 관리자 화면 초기 진입과 새로고침은 감사 로그에 남기지 않는다.
- 팀원 초대 기본 역할은 `조회자`다.
- 관리자 권한 초대 시 별도 확인 체크가 필요하다.
- 초대받은 사용자는 직접 비밀번호를 설정한다.

## 감사 로그

- 주요 성공 작업은 감사 로그에 남긴다.
  - 앱 로그인
  - CRM 로그인
  - CRM 로그아웃
  - 점검 데이터 조회
  - 점검서 생성
  - 점검서 다운로드
  - Zendesk 미리보기
  - Zendesk 발송
  - 첨부 업로드
  - 점검자 서명 등록/삭제
  - Zendesk 설정 변경
  - 팀원 초대
  - 관리자 로그 검색
- 실패 작업도 일부 감사 로그에 남긴다.
  - CRM 로그인 실패
  - 점검 데이터 조회 실패
  - Zendesk 발송 실패
  - 팀원 초대 실패
- 감사 로그에는 비밀번호, 토큰, 인증 헤더를 저장하지 않는다.

## 알려진 개선 후보

- 관리자 검색은 조회 범위의 영향을 받을 수 있어, 장기적으로 DB 컬럼 기반 검색과 날짜 범위 조회를 강화하는 편이 좋다.
- Auth 사용자 수가 많아질 경우 페이지네이션 또는 profiles 상태 동기화가 필요하다.
- 관리자 작업 필터 옵션은 고정 action catalog 또는 서버 distinct 목록으로 분리할 수 있다.
- 원본 주요 값 섹션은 기본 접힘 처리하면 가독성이 더 좋아질 수 있다.
## PDF 변환

- DOCX 생성은 서버 API에서 템플릿에 값을 주입해 처리한다.
- PDF 변환 제공자는 환경변수 `PDF_CONVERTER_PROVIDER`로 선택한다.
  - `cloudconvert`: CloudConvert Jobs API 사용
  - `convertapi`: 기존 ConvertAPI 사용
- 운영 중 변환사를 되돌릴 때는 코드 수정 없이 Vercel 환경변수만 변경하면 된다.
- 점검서 정상/비정상 체크 표시는 검정색 `✓`로 고정된다.
- 점검자 서명 이미지는 점검자 이름 오른쪽에 간격을 두고 표시되며, PDF 변환 시 식별 가능한 크기로 삽입된다.

## 점검서 상태 기본값

- 개인 설정에서 Iptables와 에이전트 연결 상태를 각각 `수집값 사용`, `정상`, `이상`으로 지정할 수 있다.
- 지정한 기본 상태는 단건 점검서와 일괄 점검서 생성에 동일하게 반영된다.
- 점검 데이터 화면의 수집 원본 상태는 변경하지 않으며, 생성되는 DOCX/PDF 체크 결과에만 기본값을 적용한다.
- 단건 점검에서는 파일 생성 전에 Iptables와 에이전트 연결 상태를 개별 변경할 수 있다.

## 메일 서버 상태 판정

- `mailServerStatus=N`만 수집된 경우 SMTP 미사용 상태로 보고 정상 처리한다.
- `checkMailServer`에 `[Line ...] :: ConnectionFailed` 같은 오류 코드나 연결 실패·거부·시간 초과·예외가 수집된 경우에만 메일 서버를 비정상으로 표시한다.
- 메일 서버 상태와 메일 관련 경고는 일괄점검의 `점검 필요` 및 자동 선택 판정에서 제외한다.
- 일괄 점검 탭의 `일괄 점검 의견`은 선택 항목의 모든 일괄 DOCX/PDF에 동일하게 반영된다.
- 일괄 점검에서 `+ 시리얼 추가`를 실행하면 새로 생성된 LO 시리얼 입력란으로 포커스가 자동 이동한다.
